01

最高优先级 · 两处动了运行代码的改动

这批改动里只有两处动了运行代码：开启 -Wall -Wextra、绘图 API 形参加宽。其余要么是纯注释，要么已被证明二进制等价（证据见 screenshots/verification_2026-09/）。先验这两处。

1-1SYNC 对齐改了代码

接线同 0-1，触发一次发波，测两沿相对抖动。

判据 抖动分布与 0-1 的记录逐点一致。这是最敏感的一项 —— Pulse_TriggerFireAll 依赖单次 CR2 写来保证 ns 级对齐，若被破坏这里立刻暴露。

1-2死区宽度改了代码

同 0-2，6 个档位逐档测上下桥死区。

判据 6 个数值与 0-2 一致，且任何一档都不能出现上下桥重叠 —— 重叠即直通，必须立即停机。

1-3OLED 逐页比对改了代码

对照 0-4 的照片逐页看。

判据 像素级一致。这是绘图 API 形参加宽唯一的验收手段 —— 绘图 API 形参由 int16_t 加宽为 int，消除了原本的隐式截断。屏幕坐标远小于上限， 理论上无差异，但必须目视确认。

02

行为契约与安全路径

这些改动理论上不影响运行，但"理论上"正需要实测来证伪。

2-1SCPI 报文逐字节对比

重发 0-5 的全部输入，逐条对响应。

判据 响应逐字节一致，特别是非法输入仍返回 0 而不是报错 —— atoi/atof 换成了 strtol/strtod，刻意保留了原有的容错语义。

2-2Fault 硬件封锁

拉低 PA15（HRTIM_FLT2）。

判据 输出立即封锁 ＋ 12V_OUT 断电 ＋ UI 弹 "Fault!" ＋ Enable 复选框自动置 0。

2-312V 互锁

断开 LTC4421 输入。

判据 12V_OUT 在一个主循环周期内断开。

2-4串口链路

上位机连续推流 OLED 镜像 ＋ SCPI 命令。

判据 无丢帧、ORE 计数不增长 —— 验证 extern 集中化没有破坏 uart_comm.c 的跨文件契约。

2-5按键与 OLED

按键长短按、双击，页面切换刷新。

判据 与改动前一致 —— 验证 static 化没有影响 Key.c 与 OLED_driver.c 的中断通信。

阶段 1、2 是针对性抽检，只覆盖"最可能被破坏的项"。这一步排除跨批次累积效应 —— 例如 static 化 ＋ 重命名叠加后被 -O3 重新优化出不同布局。

3-1H1–H10 完整跑一遍

把 0-1 到 0-5 的全部测量在新固件上重做一次，另外补上尚未抽检的两项：

H5 N 脉冲间隔 —— 会比 0-3 基线短约 70ns，这是修正不是回归。 补偿常量已按五点实测由 0.9 重新标定为 0.97。实测结果（已归档于 screenshots/verification_2026-09/）： 1/2/4/8/16µs → 1.005~1.045 / 1.98~2.00 / 3.98~4.02 / 7.99~8.01 / 15.98~16.01。 2~16µs 各点中心残差 ≤10ns，已无可检测的系统性偏差；1µs 因下限钳位停在约 1.02µs，属预期

附

两处已确认的取舍 · 回退方法

绘图 API 形参加宽让 FLASH 增加 1640 字节

136028 → 137668 字节（占用 26.26%）。原因是 int16_t 形参让 GCC 能证明取值范围、 消除部分冗余边界检查；加宽后这些检查保留，且 -funroll-loops 下寄存器压力上升。

已确认保留。 若日后改变主意：git revert 010a365，改用 .clang-tidy 抑制 narrowing 作为替代。

开启 -Wall -Wextra 让 FLASH 增加 48 字节

来自 Pulse_dPulse_SetPW 的防御性返回值检查。修的是一个当前不可达、 但将来放宽参数校验后会静默算出错误占空比的潜在缺陷。

已确认保留。 不建议回退。

本清单未覆盖 CLion 风格类检查

那批改动里列出的"冗余圆括号 / 形参可设 const / 冗余 cast"等，全部是 CLion 自带的检查， 既不是编译器告警也不是 Clang-Tidy —— -Wall -Wextra 对它们本来就是零输出。

它只影响 IDE 面板整洁度。建议在 CLion 的 Settings → Editor → Inspections 里按项关闭，而不是逐条改约 100 处源码。

出问题时二分定位
